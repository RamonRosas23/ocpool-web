# OCPOOL Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Establish a reproducible local foundation for the OCPOOL commercial platform without changing the existing public landing page.

**Architecture:** Keep the current Next.js App Router application as the single deployable application and add server-side foundation modules under src/server. Run PostgreSQL and Mailpit through Docker Compose while Next.js continues to run on the host during local development. Establish Prisma 7 with the PostgreSQL driver adapter, environment validation, structured logging, safe HTTP errors and a database health endpoint; business modules will be added in later plans.

**Tech Stack:** Next.js 15.5.24, React 19.1.0, TypeScript 5.9.x, Node.js 22.x, PostgreSQL 16, Prisma ORM 7.10.0, @prisma/adapter-pg, pg, Zod, Pino, Vitest, Playwright, Docker Compose and Mailpit.

**Spec:** docs/historicos/specs/2026-09-07-ocpool-commercial-platform-design.md

## Global Constraints

- Preserve the existing public landing page, its identity, content contract, responsive behavior and 29 passing E2E tests.
- Do not implement authentication, RBAC screens, quote builder, customer portal or commercial workflows in this plan; those are later plans.
- Use PostgreSQL as the only relational database target; do not add SQLite fallback logic.
- Use Prisma migrations for schema evolution; do not use prisma db push as the project workflow.
- Use Prisma 7.10.0 because the current Node.js 22.14.0 environment is compatible with the Prisma 7 setup and driver adapter model documented for Node 22. See the Prisma 7 PostgreSQL quickstart: https://www.prisma.io/docs/v7/prisma-orm/quickstart/postgresql.
- Keep generated Prisma client output under src/generated/prisma/ ignored by Git and regenerate it from the schema.
- Never commit .env, database credentials, generated secrets or local database volumes.
- Every task must have a focused test cycle and a logical commit.
- A task is not complete because the application compiles; its listed tests and documentation checks must pass.
- Run existing regression checks after every task that changes package.json, tsconfig.json, Next configuration or server runtime behavior.

~~~ts
import { z } from 'zod';

const serverEnvSchema = z.object({
  DATABASE_URL: z.string().url().refine((value) => value.startsWith('postgresql://') || value.startsWith('postgres://'), {
    message: 'DATABASE_URL must be a PostgreSQL connection string',
  }),
  APP_URL: z.string().url().default('http://localhost:3000'),
  LOG_LEVEL: z.enum(['fatal', 'error', 'warn', 'info', 'debug', 'trace']).default('info'),
});

export type ServerEnv = z.infer<typeof serverEnvSchema>;

export function readServerEnv(source: NodeJS.ProcessEnv = process.env): ServerEnv {
  return serverEnvSchema.parse(source);
}
~~~

- [ ] Step 3: Create the lazy Prisma adapter singleton.

Create src/server/db/client.ts:

~~~ts
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from '@/generated/prisma/client';
import { readServerEnv } from '@/server/env';

type PrismaGlobal = typeof globalThis & { __ocpoolPrisma?: PrismaClient };
let localPrisma: PrismaClient | undefined;

export function getPrisma(): PrismaClient {
  const globalWithPrisma = globalThis as PrismaGlobal;
  if (globalWithPrisma.__ocpoolPrisma) return globalWithPrisma.__ocpoolPrisma;

  if (localPrisma) return localPrisma;

  const { DATABASE_URL } = readServerEnv();
  const adapter = new PrismaPg({ connectionString: DATABASE_URL });
  const client = new PrismaClient({ adapter });

  localPrisma = client;
  if (process.env.NODE_ENV !== 'production') globalWithPrisma.__ocpoolPrisma = client;
  return client;
}
~~~

The client must be lazy so a production build can compile routes without a local .env or active database connection.

Create src/server/db/health.ts:

~~~ts
import type { PrismaClient } from '@/generated/prisma/client';
import { getPrisma } from '@/server/db/client';

export type DatabaseHealth =
  | { status: 'ok' }
  | { status: 'unavailable' };

export async function checkDatabase(client?: PrismaClient): Promise<DatabaseHealth> {
  try {
    const database = client ?? getPrisma();
    await database.$queryRawUnsafe('SELECT 1');
    return { status: 'ok' };
  } catch {
    return { status: 'unavailable' };
  }
}
~~~

- [ ] Step 4: Implement the health route.

Create src/app/api/health/route.ts:

~~~ts
import { randomUUID } from 'node:crypto';
import { NextResponse } from 'next/server';
import { checkDatabase } from '@/server/db/health';
import { logger } from '@/server/logging/logger';

export async function GET() {
  const requestId = randomUUID();
  const database = await checkDatabase();

  if (database.status !== 'ok') {
    logger.error({ requestId, database: database.status }, 'Health check failed');
    return NextResponse.json({
      status: 'degraded',
      requestId,
      services: { database: database.status },
    }, { status: 503 });
  }

  return NextResponse.json({
    status: 'ok',
    requestId,
    services: { database: database.status },
  });
}
~~~
